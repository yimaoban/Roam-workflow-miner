# 第①②阶段：筛选任务与还原真实过程

## 第①阶段：筛选适合AI改造的任务（最多5问）

### 目标

防止用户随便选一个不适合的任务。本阶段**不出任何方案**，只做筛选和确认。

### 提问顺序（循序渐进，每轮一个问题）

1. **岗位全景**：你的岗位是什么？日常工作大概包括哪几类事？（开场已问，听用户回答时心里列出候选任务清单）
2. **频率盘点**：这些事里，哪些是每周都要做、甚至每天都要做的？
3. **输入输出**：其中哪些事，交给你的时候东西是固定的（某种表格、某种请求、某种材料），做完交出去的东西也基本是固定的？
4. **痛点定位**：哪件事最让你觉得"又来了"——最耗时、最容易返工、或者最容易出错？
5. **确认聚焦**（如前4问已明确可省）：听起来X这件最值得先做，你觉得呢？

### 适配性判断标准

选中的任务理想情况应同时具备：

- ✅ 高频重复（每周至少一次）
- ✅ 有固定输入
- ✅ 有固定输出
- ✅ 中间需要整理、分析、写作、判断或分发
- ✅ 经常耗时、返工或出错
- ✅ 有一定规则，但又不是完全机械化

### 劝退场景与话术

| 场景 | 判断 | 话术要点 |
|---|---|---|
| "和领导谈战略方向" | 纯创意、无固定产出，不适合 | "这类工作AI帮不上结构化的忙。咱们换一件——你日常有没有那种'来了就知道大概怎么做，但做起来很花时间'的事？" |
| 一年只做一两次的事 | 低频，不值得做工作流 | "这个频率做工作流不划算。有没有周更、日更级别的事？" |
| "处理客户投诉" | 适合，但必须保留人工审核 | 可以选，但提前埋一句："这类工作后面设计时，我们会留人工审核点。" |
| 用户挑了最想偷懒而非最适合的 | 用标准对照说明利弊 | "X听起来很诱人，但它每次情况都不一样，AI容易帮倒忙。Y虽然不起眼，但规则清晰得多，先拿它练手成功率更高——你也可以再想想。" |

### 阶段收尾

复述确认，例如：

> 好，那我们就聚焦这件事：**每周整理各部门数据表并生成周报给总监**。接下来第二步，我会帮你还原这件事在现实里到底是怎么完成的——注意，是"真实怎么做的"，不是"应该怎么做"，这两者往往差很远。

## 第②阶段：还原一次真实完成过程（最多6问）

### 目标

还原**真实做法**，不是理想流程。用户说"我就是发个通知"时，真实过程可能是：先看领导口径 → 再看时间地点是否确定 → 确认是否要报名 → 按不同对象改语气 → 发群 → 私聊没回的人 → 做名单 → 提醒物料。

### 提问清单（按顺序，每次一个问题）

1. **触发**：这项工作通常从什么事情触发？是固定时间、别人交给你、还是临时发生？
2. **输入**：接到之后，你会先看哪些材料、信息或数据？先打开哪个文件/系统？
3. **处理顺序**：然后你实际按什么顺序处理？能不能带我走一遍上次做这件事的完整过程？
4. **沟通**：中间会和哪些人沟通？问他们什么？等他们的什么回复？
5. **交付**：最后交付给谁？交付成什么形式（表格/邮件/群消息/PPT）？
6. **跟进**：交付之后通常还要跟进什么？有没有交完又被打回来的情况？

### 追问技巧

- **用户给概括答案时**："上次做这件事，从你坐下来处理到交付，具体先点了哪个文件？"——锚定到一次具体经历。
- **用户说"看情况"时**："最常见的那种情况是什么样的？"先抓主流路径，再问一句"还有哪几种情况？"。
- **用户漏掉沟通环节时**：主动补问"这中间你有没有找人确认过什么？"
- **发现分支路径时**：简单记下，标记"分支：XXX"，第三阶段追问它们的处理差异。

### 阶段收尾

用一行流程图复述还原结果，请用户确认：

> 我复述一下你现在的真实做法：**收到模板 → 先核对X → 再找Y确认 → 整理 → 交给Z → 被打回改口径 → 重发**。有没有漏掉的、或者说得不对的地方？

确认后进入第③阶段（隐知识挖掘，核心阶段）。
