# 第④阶段：生成AI工作流方案与交付文档

## 进入时机

第③阶段四象限小结经用户确认后，才进入本阶段。开头一句话过渡：

> 好，材料齐了。现在我把它整合成一条可执行的AI工作流——包括AI接管什么、你保留什么、以及你明天就能上手用的工具。

## 文档结构（八段式，缺一不可）

生成《岗位AI工作流文档》，Markdown格式，结构如下：

### 一、工作流名称
一句话说明这条工作流解决什么问题。

### 二、原始工作流
用 **触发 → 输入 → 处理 → 沟通 → 输出 → 跟进** 的结构还原第②阶段挖出的真实做法（不是理想流程）。写得具体，保留用户提到的真实细节（找谁确认、看什么口径）。

### 三、AI改造后的工作流
用 **触发 → 输入 → AI处理 → 人工判断 → 输出 → 记录/归档 → 跟进** 的结构设计。AI处理和人工判断必须分开列出，人工判断点直接引用第③阶段挖出的隐知识。

### 四、AI可以介入的具体环节
逐项说明：
1. 哪一步可以让AI整理信息
2. 哪一步可以让AI生成内容
3. 哪一步可以让AI做分类或判断辅助
4. 哪一步可以让AI生成表格、通知、报告或话术

### 五、不能完全交给AI的环节
明确写出必须人工审核的地方，**逐条说明原因**（原因来自第③阶段的隐知识和失败案例，不是泛泛的"需要人来把关"）。

### 六、推荐工具链（两个版本）
1. **简单版**：只用一个通用AI工具完成——描述操作步骤，用户明天就能照做
2. **进阶版**：2-4个工具组合完成（可结合用户已提及的工具；用户如果在WorkBuddy里访谈，可直接建议WorkBuddy能力）

### 七、明天就能用的完整提示词
生成一条可直接复制使用的提示词，必须包含五部分：
- 背景（用户的岗位和任务场景）
- 输入材料（用户会粘贴什么）
- 处理要求（引用第③阶段挖出的隐性判断规则，写成AI必须遵守的指令）
- 输出格式
- 审核提醒（提示用户AI输出后自己要检查什么）

**这是整份文档含金量最高的部分**：把用户的隐知识直接翻译成提示词里的规则，而不是写一条通用提示词。

### 八、人工检查清单
一份5-8条的检查清单，帮用户判断AI输出是否可靠。来源：第③阶段的质量标准、不能出错的细节、历史翻车点。写成可勾选格式（- [ ]）。

## 写作要求

- 全文用用户的真实语境（他的行话、他提到的系统名、他同事的角色），不发明用户没提过的细节
- 隐性规则必须具体到可执行（"先看领导最新口径，以群里最后一条为准" ✅，"注意口径一致" ❌）
- 涉及敏感信息/合规/人事的环节，一律保留人工审核并写明原因
- 长度适中：用户能读完为标准，避免堆砌

## 交付动作

1. 将文档保存为 .md 文件，**UTF-8 with BOM 编码**，路径默认 `D:\workbuddy工作专区\岗位工作流\<岗位或姓名>-<任务名>-AI工作流.md`（目录不存在则创建；用户另有指定则从其指定）
2. 告知用户文件绝对路径
3. 结尾给出下一步建议（三选一，按用户状态）：
   - "先用一周，遇到不对劲的地方记下来，我们再迭代"
   - "想继续的话，可以再挖你岗位上另一件事"
   - "也可以把这条工作流搭成自动化/智能体，让它真的跑起来"
4. 温馨提醒：这份文档里最值钱的是第七部分的提示词和第八部分的检查清单——前者替他干活，后者替他把关。
